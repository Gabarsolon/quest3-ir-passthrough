**Quest IR now runs directly on the headset after temporary root is established.**
The user confirmed that the corrected build works on Quest 3, Horizon OS v79,
build **51154110174900520**. This is a preview for that tested firmware.

### Install and run

Download **quest-ir-v0.2.0-preview.1.apk** below and install it with your usual
APK installer or authorized ADB:

```powershell
adb install -r quest-ir-v0.2.0-preview.1.apk
```

With temporary root already active, stop any laptop IR controller, enable
normal system passthrough, and open **Quest IR** under **Unknown Sources**.
Select **Start IR**. You can close the app and disconnect the laptop; capture,
calibration, injection, and the watchdog all run on the headset.
Select **Stop IR / restore RGB** in the app to stop. Normal runs have no timer.

**Root recovery after reboot is still separate.** The APK does not run an
exploit or provide persistent root. Restore temporary root with the existing
recovery launcher, then open the app again.

### Changes

- Native ARM64 supervisor with embedded Frida Core **17.24.3**. No laptop
  Python process, ADB connection, separate Frida server, or Wi-Fi is needed
  while IR runs.
- Per-headset factory calibration is computed locally and DMA descriptors are
  discovered fresh for the current boot.
- Start/Stop, brightness, linear/cubic/SGSR filtering, optional edge AA, and
  optional 120 Hz display timing in the headset app. Options apply per run;
  default filtering is linear, AA is off, and display timing is preserved.
- Fixes an RPC reply race that could end IR a few seconds after startup.
- Shares frame files with the compositor while keeping the controller and
  logs in a separate private RAM directory.
- Rejects overlapping native/laptop controllers and retains RGB cleanup,
  local heartbeat monitoring, and temporary display restoration.

### Scope and validation

Source input remains **640x512 per eye, approximately 60 distinct images/sec**
in previous measurements. The remap is 1280x960 per eye. A 120 Hz display
does not enable 120 FPS capture or full-resolution sensor output.

Validation includes 37 Python tests, publishing checks, 2,000 on-device RPC
round trips (1,000 with binary payloads) in an owned test process, calibration
comparison with the NumPy implementation, root preflight from the app's own
uid, a sustained native IR run with zero reported rendering/pose errors, and
the user's visual confirmation. Extended sessions and repeated transitions
between applications still need broader validation.

The APK persists as an ordinary installed app. Root, compositor hooks, extracted
binaries, frame files, and runtime logs remain temporary under
`/dev/quest3-ir-session`. No firmware, boot/system/vendor/odm partition writes,
bootloader unlock, or persistent root. Existing root helpers in userdata survive
reboot; root and runtime patches do not.

The release APK is signed with the same local development key as the tested
app. Independently built APKs use a different key. SHA256SUMS.txt covers the
downloadable APK; source archives are available below.
