Updated RAM-only stereo IR passthrough prototype for Quest 3, Horizon OS v79
build **51154110174900520**. This remains a laptop-controlled release;
headset-only operation is the next development step.

- Isolates compositor resources per EGL context and supports protected outputs.
  Browser over Virtual Desktop passed a short visual test. Repeated app switches
  and extended sessions still need validation; this is not a general stability
  guarantee for every app.
- Uses an isolated, matching Frida **17.24.3** client/server. Older 17.17 startup
  crashes prompted this update. Calibration transfer now fits the newer runtime's
  message limit.
- Adds optional `--brightness 0..4` and `--display-refresh 120`. The display
  request is restored on normal stop. Camera input remains **640x512 per eye,
  approximately 60 distinct images/sec**; a 120 Hz display does not create a
  120 FPS camera stream. No full-resolution IR stream was found.
- Adds the checked USB IonStack recovery launcher for the already-staged payload.
  It skips exploitation if root is active, verifies build/kernel/payload/config,
  disables Wi-Fi during exploitation, and enables Wi-Fi and requests paired
  Wireless debugging after success. Root recovery can hang or reboot the headset.
- Falls back from an unavailable saved wireless target to this same Quest's USB
  connection. Explicit `--serial` selections are preserved.
- Keeps linear filtering and anti-aliasing off by default. Cubic, SGSR, brightness,
  and display timing are options for each run.

Prepare the matching runtime once:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\update_frida_runtime.ps1
```

With temporary root already active and normal passthrough enabled:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\run_ir.ps1 --display-refresh 120 --brightness 1
```

Ctrl+C restores RGB. `python .\tools\system_passthrough.py --stop` also stops
the controller. Root recovery is separate: use `tools\root_ionstack.ps1` over
USB when needed; this requires the previously staged payload and configuration.

Validation: 34 Python tests and the PowerShell publishing checks passed. The
recorded two-minute run on Frida 17.24.3 completed without a compositor restart.
Remaining limits include source resolution, near-field parallax, and incomplete
long-running app-transition validation. The local experimental Fugu root port is
not included or presented as a working alternative.

New headset binaries, images, and logs stay in `/dev/quest3-ir-session` tmpfs.
No firmware/boot/system/vendor/odm partition writes, bootloader unlocking, or
persistent root. Existing root helper files in userdata survive reboot;
temporary root and runtime hooks do not.
